# Инструкция по установке Telegram Agent MCP

## Назначение

Сервер работает по `stdio` и предоставляет три инструмента:

- `telegram_status` — проверка бота, чата, префикса и монитора;
- `telegram_send_message` — отправка текста в Telegram;
- `telegram_read_commands` — ручное чтение, доступное только при выключенном встроенном мониторе.

При включённом мониторе команды из Telegram автоматически запускают дочернюю сессию Codex в проекте. Последующие команды продолжают эту сессию. При смене префикса старая дочерняя сессия удаляется, а следующая команда создаёт новую.

## Установка пользователем

1. Распакуйте архив в корень нужного проекта, сохранив имя папки `telegram_agent_mcp`.
2. Откройте PowerShell в этой папке.
3. Выполните:

```powershell
.\setup.ps1
```

4. Ответьте только на вопросы о незаполненных параметрах. Ввод токена скрыт.
5. Подключите сервер к MCP-клиенту. Точка запуска — `node dist/index.js`, рабочая папка — распакованная папка MCP.
6. Перезапустите MCP-подключение и вызовите `telegram_status`.

Установщик:

- проверяет наличие Node.js 20+ и npm;
- сохраняет локальный `.env` в UTF-8;
- создаёт `data`;
- выполняет `npm ci` по `package-lock.json`;
- собирает `dist/index.js`.

## Подключение Codex

Если установку выполняет Codex, достаточно сообщить агенту:

> Подключи Telegram MCP из папки `telegram_agent_mcp` в корне текущего проекта, выполни setup, перезапусти подключение и проверь telegram_status.

Пользователю не требуется искать абсолютный путь. Агент определяет его по текущему проекту. Универсальный шаблон для других MCP-клиентов находится в `mcp-config.example.json`.

## Настройки `.env`

```dotenv
TELEGRAM_BOT_TOKEN=123456789:replace_me
TELEGRAM_CHAT_ID=-1001234567890
TELEGRAM_USE_PREFIX_FILTER=true
TELEGRAM_COMMAND_PREFIX=cod
TELEGRAM_STATE_FILE=data/state.json
TELEGRAM_MONITOR_ENABLED=true
TELEGRAM_MONITOR_STATE_FILE=data/monitor-state.json
TELEGRAM_MONITOR_POLL_TIMEOUT=30
```

Обязательны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Значения путей могут быть относительными: они вычисляются от папки MCP.

`TELEGRAM_MONITOR_POLL_TIMEOUT` допускает значения от 1 до 50 секунд. Изменение префикса применяется после завершения текущего long-poll запроса. Изменение `TELEGRAM_MONITOR_ENABLED` требует переподключения MCP.

Префикс сопоставляется целиком. Для префикса `co` подходят `co команда`, `co: команда` и `co - команда`; строка `cod команда` не подходит.

Если MCP-клиент нельзя перезапустить немедленно, монитор можно временно держать активным отдельным host-процессом:

```powershell
npm run monitor
```

Одновременно должен работать только один принимающий монитор. При обычном запуске через MCP-клиент отдельный host не требуется.

## Автоматически создаваемые файлы

При установке или первом запуске создаются:

- `.env` — установщиком после ввода настроек;
- `node_modules` — командой `npm ci`;
- `dist` — командой `npm run build` (готовый `dist` также есть в архиве);
- `data` и файлы позиции чтения — установщиком и сервером;
- `monitor.lock` и `telegram-agent-session.json` — сервером по мере необходимости.

Эти локальные файлы не входят в установочный архив, кроме предварительно собранного `dist`.

## Проверка

После подключения вызовите `telegram_status`. Для прямой проверки из папки MCP можно выполнить:

```powershell
node .\mcp-monitor-test.mjs
```

Затем отправьте в настроенный чат команду, например `cod тест связи`. Бот должен сначала подтвердить приём, затем прислать итоговый ответ агента.

## Диагностика

- `TELEGRAM_BOT_TOKEN is required in .env` — токен отсутствует или пуст.
- `TELEGRAM_CHAT_ID is required in .env` — ID чата отсутствует.
- `chat not found` — неверный ID либо бот не добавлен в чат.
- Команды не поступают — проверьте точное совпадение префикса и состояние `monitorState` в `telegram_status`.
- После изменения префикса подождите завершения long poll (до указанного timeout).
- Монитор в состоянии `standby` — входящие обновления уже читает другой процесс этого MCP.
- Инструменты не появились — пересоберите `npm run build` и переподключите MCP.

## Сборка установочного ZIP

Для выпуска новой версии выполните:

```powershell
.\build-package.ps1
```

Сборщик включает только установочные исходники, документацию и готовый `dist`. Перед упаковкой он отклоняет `.env`, `data`, `node_modules` и известные машинно-зависимые пути.
